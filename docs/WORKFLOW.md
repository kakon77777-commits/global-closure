# Global Closure：從完整實作到交付

本專案保存可執行的軟體，也提供 `global-first-completion` 的具體使用案例。

## 文件盤點需求

> 幫我做一個離線 Markdown 研究稿盤點工具：遞迴掃描資料夾、擷取標題與字元數、找出內容完全相同的稿件，輸出 JSON 與 Markdown 報表。保留原稿，支援中文路徑，附 Windows PowerShell 用法、範例資料與測試。

主路徑是命令列 → 掃描器 → 共用資料模型 → 兩種報表。四個部分接通後才執行集中驗證，沒有把第一個模組通過視為整個工具完成。

## 紀錄合併需求

> 合併三批研究稿紀錄，統一欄位、全半形稿號與狀態。相同紀錄去重並保留來源；衝突資料保留不同版本；不同稿號的同名稿件不可合併。隔離無效資料，統計各系列與狀態。

原示範的初輪十項檢查都通過，但全域覆蓋檢查發現：只有衝突稿的「記憶」系列消失了。共同原因是統計桶只從已確定稿件建立。修復後，先從所有有效格式的版本建立系列，再分別計算已確定稿件及衝突。

本儲存庫保留這個修復與回歸測試，包括跨系列衝突的情況。紀錄合併程式已從對話中的一次性計算整理成可重跑的 `record_merge.mjs`，並增加檔案輸入、JSON 輸出與 CLI 結束碼。

## 如何套用技能

| 步驟 | 對應到本專案 |
| --- | --- |
| 範圍 | 把軟體、輸出、原稿保留、文件及交付列為同一個需求 |
| 完整實作 | 接通掃描／合併與輸出，不只完成局部函式 |
| 首輪驗證 | 集中執行行為測試與真實命令列範例 |
| 根因修復 | 根據觀察到的失敗，修改影響多個結果的共同原因 |
| 針對性驗證 | 修復後先檢查受影響的行為 |
| 最終驗證 | 從乾淨解壓的交付內容重跑必要檢查 |
| 交付 | 保存原始碼、範例、測試、報表與技能，核對 GitHub 結果 |

若首輪沒有發現缺陷，修復階段可以沒有變更，不需要故意製造錯誤。測試數量不是完成程度；完整需求的可執行證據才是判斷依據。

這是方法示範，不是跨模型比較或已證明節省時間／Token 的實驗。先前文件工具曾因執行環境斷線中止；本次發布重新驗證恢復後的實際原始碼，不能用紀錄合併示範的通過取代文件工具的驗證。
